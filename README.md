# WP 自刻主題起案包

野薑設計做 WordPress 客戶站的起案包：一套**可直接啟用的古典 PHP 主題骨架**，
加上開站、切版、部署與協作的完整規範文件。

目的是讓下一個客戶站**不必從零開始**——clone 下來、跑一支腳本改名，
就有一個能跑、能部署、有後台設定頁的素站，並且知道每一步該怎麼做、哪些坑不用再踩一次。

由[野薑設計](https://www.gingerdesign.com.tw/)維護。歡迎自用與修改；
它反映的是我們自己接案的工作方式，不保證適合你的流程。

## 這包做了什麼決定

**技術路線**：古典 PHP 模板 + ACF 欄位。
**不使用** Gutenberg、Block Pattern、`theme.json`，也不使用 Elementor 這類頁面建構器。
版面是設計稿切出來的固定結構，可變的只有文案與圖片，那些走 ACF 讓客戶在後台改。

**內容分三層**，這是整包最重要的觀念：

| 層 | 存哪 | 進 git 嗎 |
|---|---|---|
| 設定頁的「存在」 | `functions.php` PHP 註冊 | ✅ |
| 欄位「定義」（有哪些欄位） | `acf-json/` | ✅ |
| 欄位「值」（實際填了什麼） | 各站自己的資料庫 | ❌ |

所以主題剛部署到新環境時，前台看到的都是版型檔裡的回退值——那是正常的，不是壞掉。

**開發與部署**：Local by Flywheel 本機開發（官方就地開發，不用 symlink），
`deploy.sh` 走 tar over SSH 部署到正式站，含五層驗證。
部署**不會**自動啟用主題——那一步刻意留給人做。

## 完成後怎麼用

### 這包是設計成「跟 AI 一起用」的

**光把這個 GitHub 連結貼給 AI 沒有用**——純聊天介面的 AI 只讀得到網頁上的文字，
沒有檔案系統可以跑腳本、沒有 Local 站可以驗證，也改不了你的主題檔。

正確的用法是 **clone 到本機，然後用 AI 編輯器打開這個資料夾**：

```bash
git clone https://github.com/gingerdesigndev/wp-theme-starter-kit.git
cd wp-theme-starter-kit
claude          # 或用 Cursor / VS Code 開這個資料夾
```

然後直接跟它說「**我要開新站**」。

進到這個資料夾的 AI 會自動讀到 `AGENTS.md`（Claude Code 讀 `CLAUDE.md`，它指向同一份），
知道這是什麼專案、該讀哪份文件、有哪些硬規則、以及哪些事它做不到。
`.claude/skills/` 裡的 skill 在 Claude Code 底下會依你說的話自動觸發，
你不需要記任何指令，也不必先讀完所有文件。

### 起案

```bash
# 把整包複製到目標 Local 站的 wp-content/themes/，在那份複本上跑：
./起案.sh <主題slug> <CSS前綴> "<主題顯示名>"
```

`起案.sh` 會把出廠的 `starter-theme` / `st-` 換成新站的名字、產生站台專屬檔，
並印出**只有人能做、AI 做不到**的三件事（裝 SSH 公鑰、產應用程式密碼、後台啟用主題）。

然後從 `docs/00-開站六步.md` 開始。

### 日常：切一塊版

開站之後最高頻的動作，一天可能做十幾次。你要做的只有四步：

**1. 在 Figma 選取要切的頁面或區塊**

點一下那個 frame／區塊，看左側圖層面板確認選中的是你要的那一層。
選錯層（例如選到整個 page 而不是那一區）拿到的連結範圍就會錯，AI 會切出多餘的東西。

**2. 按右上角藍色的 `Share`**

**3. 複製 Dev Mode 連結**

在 Share 面板選 `Copy link to selection`。複製到的網址會帶 `?node-id=...`，
那個 `node-id` 就是 AI 要抓的目標。
如果面板裡沒看到 Dev Mode 的選項，先按右上角的 `</>` 切到 Dev Mode 再複製。

**4. 把連結貼給 Claude，說「切這塊」**

```
切這塊 https://www.figma.com/design/xxxxx/專案?node-id=8104-2540
```

剩下的 AI 自己做：讀 `design-system.md` 確認有哪些 token → 從 Figma 抓結構、尺寸與素材
→ 決定哪些內容開成 ACF 欄位（客戶會想自己改的）、哪些寫死 → 寫 `template-parts/`
的區塊檔與 CSS → 同步更新 `design-system.md`。

**然後你只要做兩件事**：自己開真實瀏覽器看一眼（headless 截圖在滿版元素上會騙人，
別讓 AI 用截圖跟你保證版面沒問題），沒問題就跟它說「部署」。

> ⚠️ **第一次要先接上 Figma。** AI 要透過 Figma 的 MCP 連線才讀得到設計稿內容。
> 沒接上的話它只會拿到一串網址、看不見裡面——這時它該直接說「我讀不到」，
> 而不是照著檔名或你的描述猜版面。它要是開始猜，停下來先把 MCP 接好。

### AI 幫不到你的地方

先講清楚免得期待落差。AI 能做的是它碰得到的部分：寫碼、切版、部署、驗證、
上傳素材、建頁面。碰不到的是上面那三件，加上客戶的 Figma、主機面板與 DNS
——這些需要你主動提供或親自操作。

## 讓 AI 接管後台（上架素材、建頁面）

主題「碼」走 SSH，後台「內容」走**另一條完全獨立的管道**：
WordPress REST API + 應用程式密碼。兩條缺一不可，權限互不影響。

接上之後 AI 可以：**上傳媒體素材**、建立與編輯頁面／文章、調整選單、填 ACF 欄位值。
**做不到的是啟用主題**——WordPress 核心的 REST API 沒有這個端點，那一步一定要人到後台點。

### 怎麼產生

WP 後台 → **使用者 → 個人資料**（用管理員那個帳號）→ 捲到頁面最下方
**「應用程式密碼」** → 輸入一個好認的名稱（例如 `claude-code`）→ 按「新增應用程式密碼」
→ **複製顯示出來的那一串，它只會顯示這一次。**

這一步只有你能做，AI 沒有後台登入權。但**產生之後的事都可以請 AI 協助**：
寫設定檔、測試連線、確認權限夠不夠、之後的上架與建頁面全部交給它。

### 怎麼交給 AI 用

寫進**專案根目錄外**的 `.env`（權限 `600`、放在所有 repo 之外，不進版控）：

```bash
WP_URL='https://<你的網域>'
WP_USER='<管理員帳號>'
WP_APP_PASSWORD='xxxx xxxx xxxx xxxx xxxx xxxx'
```

⚠️ **三個值都要用單引號包住。** 應用程式密碼的值含空格，沒有引號的話
shell 會把它拆開、變數變成空的，然後你會看到一連串「認證失敗」卻找不到原因。

⚠️ **不要把密碼貼進對話。** 貼進去它就會明文留在對話紀錄裡。
寫進 `.env`，AI 自己讀得到，也不必經過你的手。

### 怎麼收回

回同一個頁面，按那組密碼旁邊的「撤銷」。撤銷後 AI 立刻失去後台存取權，
SSH 那條管道完全不受影響——反之亦然。這就是兩條管道分開的用意。

## 目錄導覽（完成後）

| 位置 | 是什麼 |
|---|---|
| `style.css` / `functions.php` / `*.php` | 主題骨架 |
| `template-parts/` | 版面區塊，含兩個示範 |
| `acf-json/` | ACF 欄位定義 |
| `docs/` | 八份規範文件 ← **動手前先讀** |
| `.claude/skills/` | 隨包 skill，接手的 agent 不必安裝任何東西 |
| `CLAUDE.md` | 保底導讀，skill 沒觸發時從這裡也能找到路 |
| `deploy.sh` / `起案.sh` | 部署與起案腳本 |
| `design-system.md` | 全站樣式的唯一真相源 |

`docs/05-踩坑清單.md` 是這包裡最省時間的一份——遇到怪事先查它，別自己從頭追。

## 給接手的工程師

這包預設你**讀不到原作者機器上的任何設定**，所以規範與 skill 都隨包附上、自給自足。
代價是副本會漂移：起案後的每個站都是獨立複本，正本更新不會自動回流。

在某個站學到、對下一個站也有用的教訓，寫進該站的 `docs/回饋正本.md`，
之後由維護者人工回灌正本。每個站起案時的正本版本會記在它的 `HANDOFF.md` 開頭。
