# 開站六步

> 這是一個站——不論是既有站搬過來、還是全新開的——從零到「AI 能協作」的完整路徑。
> 讀完這份約 5 分鐘，讀完就能照著動手。
>
> AI 這邊有對應的 skill（`wp-client-site-bootstrap`），你說「開新站」「把站抓下來改」
> 時會自動觸發，細節都在裡面；**這份講的是人要做什麼、AI 要做什麼、順序為什麼是這樣**。

---

## 先選一條起點分支

開站的路徑分兩種，差在第 1、2 步；第 3 步之後完全一樣。先判斷自己是哪一種：

### 分支 A：遷移既有站（雲端已經有一個站，要搬過來改）

**第 1 步：人工搬站，不要指揮 AI 操作搬站工具。**

用 **WPvivid**（或同類搬站外掛）把雲端主機的站匯出、匯入到本機 Local 站。
⚠️ 備份檔在 nginx 主機上常可公開下載（`.htaccess` 無效），抓完立刻從外掛後台刪掉並 `curl -I` 驗 404
（見 `docs/05-踩坑清單.md`）。
人工點幾下比讓 AI 操作搬站工具的 UI 划算得多——那類工具是圖形介面導向的，
AI 沒有實質優勢，只會拉長時間。

**第 2 步：確認站真的跑起來，並停用舊的頁面建構器外掛。**

用**官方就地開發**：把這個 repo 設定成 Local 站的 theme 資料夾本身，**不要用 symlink**
（原因見 `docs/05-踩坑清單.md`「symlink 斷鏈」一條）。

確認內容都在之後，跟 AI 說**停用舊的頁面建構器**（Elementor、Divi 這類）。

⚠️ **硬依賴，順序不能顛倒**：

```
其餘頁面遷移完 → 才能停用頁面建構器 → header/footer 才會是自刻主題的
```

頁面建構器常常自帶 Theme Builder，會用 output buffering 攔截主題的
`get_header()` / `get_footer()`，改印它自己的範本——只要還有頁面依賴它，
現在停用就會讓那些頁面全部塌掉。**先把其餘頁面遷移完，最後才處理頭尾**，
這條踩過一次代價很高，不要提前停用。

### 分支 B：全新建站（沒有既有站，直接開新的）

跳過第 1 步——沒有東西要搬。

第 2 步只需要確認 Local 站的 **WordPress 版本與 PHP 版本**符合主題需求，不必處理停用外掛的事。

其餘（第 3 步起）與分支 A 完全相同。

## 六步表

| # | 步驟 | 誰主導 | 你要做的事 | 這步的坑 |
|---|---|:---:|---|---|
| 1 | **從雲端主機搬到 Local**（僅分支 A） | 你 | 用搬站外掛人工搬站 | 別指揮 AI 操作搬站工具，那不划算 |
| 2 | **確定 Local 可以啟用修改** | AI | 確認站真的跑起來、內容都在 | 官方就地開發，**別用 symlink**；分支 A 要跟 AI 說停用舊頁面建構器 |
| 3 | **將修改上傳到雲端主機** | AI | 確認部署目標正確 | `./deploy.sh`。遠端常常沒有 rsync → 走 tar over SSH（見 `docs/04-部署SOP.md`） |
| 4 | **允許 AI 連線 SSH** | **你** | **親手把公鑰裝上去**（要輸密碼，AI 不碰） | `ssh-copy-id` 要在**你自己的電腦**跑，不是 SSH 進伺服器之後 |
| 5 | **開後台權限給 AI** ⭐ | **你** | 跟 AI 說：**「我授權你操作後台權限，請你協助我產生 Application Password / .env 檔案」** | AI 會引導你、把 `.env` 和指令備好、最後驗證——但**後台按那兩下只能你來**（它沒有登入權）。值要用**單引號**包住（含空格，沒引號會整個失效） |
| 6 | **驗收主題是否正確上傳** | AI | 讀它的驗證報告，別只信一句「好了」 | 六層驗證（第 0 層：工作目錄要乾淨），只做第一層不算數 |

### 為什麼第 5 步最關鍵

第 4 步（SSH）只給 AI **檔案**能力——它能改主題、能部署，但**碰不到資料庫**。

沒有第 5 步，「建頁面、改選單、改設定、查主題狀態」全部都要人工點，AI 只能在旁邊給你貼操作步驟。
**開了第 5 步，AI 才真的能端到端把事做完。**

### 順序上有兩個硬依賴

上面是照工作流程的順序列的，但實際執行時要注意：

- **第 4 步必須在第 3 步之前** —— 沒有 SSH 就沒有部署管道。
- **第 2 步必須在第 3 步之前** —— 本機改不動，就沒東西可傳。

所以真正動手的順序比較接近：**1 → 2 → 4 → 3 → 5 → 6**（分支 B 沒有第 1 步，就是 **2 → 4 → 3 → 5 → 6**）。

## SSH 與 Application Password 的實際指令

**SSH**：讓 AI 產金鑰 → 它給你公鑰 → **你自己**裝上去：

```bash
# ⚠️ 在「你自己的電腦」上跑，不是 SSH 進伺服器之後！
ssh-copy-id -i ~/.ssh/<專案>.key.pub -p <PORT> <USER>@<HOST>
```

**Application Password**：直接跟 AI 說 **「我授權你操作後台權限，請你協助我產生 Application Password / .env 檔案」**，它會引導你走完並驗證。分工是這樣（**這兩件事只有你能做**）：

1. **產生密碼**：WP 後台 → 使用者 → 個人資料 → 應用程式密碼 → 命名 → 產生 → 複製（只顯示一次）。
   AI 沒有登入權，這步它做不到；而且 REST 雖有建立 app password 的端點，但呼叫它本身就要先有憑證——雞生蛋。
2. **把值填進 `.env` 並自己執行**（**不要把密碼貼在對話裡**，那會讓它明文留在紀錄）：

```bash
# ⚠️ 放在 repo 外，不是專案根目錄！repo 根目錄就是主題根目錄本身，
#    會被 deploy.sh 整包打包上傳——密碼放在專案根目錄裡等於明文送上公開網址。
cat > ~/wp-secrets/<專案>.env <<'EOF'
WP_URL='https://example.com'
WP_USER='帳號'
WP_APP_PASSWORD='xxxx xxxx xxxx xxxx xxxx xxxx'
EOF
chmod 600 ~/wp-secrets/<專案>.env
```

> **值一定要用單引號包住** —— Application Password 含空格，沒引號 shell 會解析失敗、變數全空。

**撤銷**：後台「應用程式密碼」一鍵刪除，不影響帳號本身。

更完整的權限模型（兩條管道分別碰得到什麼、怎麼撤銷）在 `docs/06-協作制度.md`。

## 外掛基線：哪些外掛要一起帶到新站

主題不是孤島，它依賴幾個外掛；開新站時先把這張表過一遍，不要等前台壞了才發現少裝。
盤點依據是**掃主題程式碼**（`function_exists`、hook 名、`acf-json/`），不是看上一個站的啟用清單——
Local 複製站常有外掛被刻意停用，光看 Local 會誤判。

| 類別 | 外掛 | 為什麼 |
|---|---|---|
| **硬依賴**（沒裝主題會壞） | ACF PRO | options page、Repeater、ACF Block 都是 PRO 功能，免費版不夠 |
| | Rank Math | 全站 `<title>`／description／og 由它輸出，主題只掛 fallback 圖；後台的全域 OpenGraph 圖要**保持不設**，設了會蓋掉主題 filter |
| **功能性依賴**（主題有針對它寫碼） | Default Featured Image | 主題用 `dfi_thumbnail_id` filter 擋分享圖、用 `dfi_image_id` 判斷「有沒有自己的精選圖」（見 `docs/08-相關文章與卡片邏輯.md`） |
| | Post Views Counter | 熱門文章 `orderby post_views` |
| | EWWW Image Optimizer | 主題找 `xxx.jpg.webp` 兄弟檔；衍生檔不進 git，鏡像部署會刪掉正式站的、外掛會重生 |
| **營運必要**（野薑的客戶站標配） | FluentSMTP | 表單信要寄得出去 |
| | WP Activity Log | 客戶後台操作紀錄，出事能追 |
| | AJAX Login and Registration modal popup PRO | 客戶要求的登入體驗 |
| | Pixel Cat Premium | GA4／FB 像素與 CTA 事件（見 `docs/09-GA與Pixel-Cat追蹤.md`） |
| | WP Rocket | 頁面快取；部署後要清（`docs/04-部署SOP.md` 第六節） |
| | Redirection | 舊站 301 表 |
| **不帶走** | Elementor 系列、Blocksy Companion、Easy Table of Contents、Simple CSS、主機商的 mu-plugins | 頁面建構器會吞 header/footer；目錄主題自己做並關掉外掛的 |

Local 複製站上**刻意停用**的通常是 WP Rocket、FluentSMTP、WP Activity Log（避免本機寄信、改 wp-config），
以及 Pixel Cat（避免量測腳本的假流量打進正式站 GA）。停用不代表可省，表裡的「營運必要」一律要裝。
