## 一、渲染只有一份：查詢與卡片分開

全站所有「一排文章卡」——首頁區塊、404、彙整頁、單篇相關文章——**卡片 HTML 只有一份函式**。
它吃一個已經查好的 `WP_Query`，吐卡片；各頁、各區塊只負責決定「撈哪些、什麼順序」。

```php
function st_render_cards(WP_Query $q) {
    if (!$q->have_posts()) return '';
    ob_start(); ?>
    <div class="st-postcards">
      <?php while ($q->have_posts()): $q->the_post(); ?>
      <article class="st-postcard">…</article>
      <?php endwhile; ?>
    </div>
    <?php
    wp_reset_postdata();
    return ob_get_clean();
}
```

**為什麼要這樣拆：**

- 卡片改一個字（日期格式、摘要字數、`loading="lazy"`）全站同步，不會漏一處。
  實案裡日期格式曾經四處各寫死一份 `'Y/m/d'`，後台改了設定前台不跟——收成一份就不會再發生。
- 彙整頁要自己控制分頁（`paged`、`max_num_pages`），而區塊查詢為了省一次 COUNT 會設
  `no_found_rows => true`；查詢與渲染綁在一起時這兩種需求打架，拆開就各自成立。
- 審查時只要證明「查詢回傳的 id 序列沒變」，就等於證明「畫面沒變」。

**撈 id 再渲染**是配套：先用 `fields => 'ids'` 把各層候選湊成一個 id 陣列，最後一次
`post__in` ＋ `orderby => 'post__in'` 查出來渲染。順序由陣列決定，不交給 WP 的 orderby。

```php
$q = new WP_Query([
    'post_type'           => 'post',
    'post_status'         => 'publish',
    'post__in'            => $ids,
    'orderby'             => 'post__in',   // 順序＝陣列順序
    'posts_per_page'      => count($ids),
    'ignore_sticky_posts' => true,
    'no_found_rows'       => true,
]);
echo st_render_cards($q);
```

## 二、相關文章的優先序：逐層補滿、總量固定

單篇尾段「你可能也會感興趣」的規格通常是**總量固定**（例如 3 篇）、**湊不滿多少顯示多少**。
撈法是一個單一清單，分幾層由「最相關」到「最寬鬆」依序補，每層只補到差額為止：

| 層 | 撈什麼 | 什麼時候會落到這層 |
|---|---|---|
| 0 | 與本篇**共用任一標籤**、且在同一大類底下的文章 | 編輯有打標籤時 |
| 1 | **同大類**（父分類）最新文章 | 第 0 層不足 |
| 2 | **同主題子分類**（例：同症狀、同產品線）的另一種內容 | 第 1 層不足 |
| 3 | 整包最新（排除不該出現的子樹） | 最後保險 |

三條規則貫穿每一層：

1. **`exclude` 累積**：每一層的 `post__not_in` 都是「自己 + 前面所有層已選的 id」，
   同一篇不會在兩層重複出現。
2. **只補差額**：`posts_per_page => $limit - count($ids)`。
3. **層與層之間的順序要保住**：最後用 `post__in` 渲染，第 0 層在前、補位在後。

```php
function st_related_ids($post_id, $limit, $group_cat, $topic_cat, $all_cat) {
    $base = ['post_type' => 'post', 'post_status' => 'publish', 'fields' => 'ids',
             'ignore_sticky_posts' => true, 'no_found_rows' => true];
    $ids  = [];
    $step = function (array $args) use (&$ids, $base, $post_id, $limit) {
        if (count($ids) >= $limit) return;
        $args['posts_per_page'] = $limit - count($ids);
        $args['post__not_in']   = array_merge([$post_id], $ids);
        $ids = array_merge($ids, get_posts($base + $args));
    };
    $tags = wp_get_post_tags($post_id, ['fields' => 'ids']);
    if ($tags && !is_wp_error($tags)) $step(['cat' => $group_cat, 'tag__in' => $tags]);  // 0
    $step(['cat' => $group_cat]);                                                        // 1
    if ($topic_cat) $step(['cat' => $topic_cat]);                                        // 2
    $step(['cat' => $all_cat]);                                                          // 3
    return $ids;
}
```

**第 0 層的對應關係放在標籤、不寫在程式裡。** 編輯在後台把服務介紹文打上主題標籤，
案例文本來就有同一組標籤，兩邊對得上就撈得到；要調對應改標籤即可，不用改碼。
`cat` 與 `tag__in` 在 `WP_Query` 是 AND，所以只會撈到「同大類底下、帶任一相同標籤」的文章。

**代價要先講**：打了標籤的服務介紹文也會出現在標籤彙整頁、側欄標籤計數會加一；
編輯挑到泛用標籤（例如「保養」這種跨大類都在用的字）會把不相干的案例撈進來。審查這類改動時**要連標籤清單一起看**。

## 三、精選優先：ACF 開關＋「指定優先、最新補位」

客戶要「首頁這一排我自己挑」時，不要用 WordPress 的置頂（sticky）：

- 置頂是全站一份，分不出「首頁區塊要 A、彙整頁不要」。
- 主題為了版面穩定通常全部 `ignore_sticky_posts => true`，置頂根本不生效。

做法是文章編輯頁側欄一個 ACF true/false 開關（post meta `is_featured`），取精選 id 的函式
只認 `'1'`（ACF 的 true/false 存 `'1'`／`'0'`，沒碰過的文章根本沒有這筆 meta，所以用等號比對、
不用 `EXISTS`）：

```php
function st_featured_ids($cat_id, $count, array $exclude = []) {
    $args = ['post_type' => 'post', 'post_status' => 'publish', 'fields' => 'ids',
             'posts_per_page' => $count, 'cat' => $cat_id,
             'meta_query' => [['key' => 'is_featured', 'value' => '1', 'compare' => '=']],
             'orderby' => 'date', 'order' => 'DESC',
             'ignore_sticky_posts' => true, 'no_found_rows' => true];
    if ($exclude) $args['post__not_in'] = $exclude;
    return array_map('intval', get_posts($args));
}
```

呼叫端的規則是「精選在前（依日期新到舊）、不足用同分類最新補滿、精選超過 `$count` 取最新的
`$count` 篇」。**沒有任何文章勾精選時，走原本的單一查詢，輸出要逐字相同**——這是第五節的審查第一關。

要上後台「快速編輯」也勾得到這個開關時，`save_post` 只攔帶 `_inline_edit` nonce 的那次提交，
編輯頁的儲存交給 ACF；列表欄輸出 `data-featured="1|0"` 給 JS 回填。不分辨提交來源的話，
編輯頁存檔時「checkbox 沒送＝不勾」會把 ACF 剛存的值蓋掉。

## 四、「預設關閉、只開給指定呼叫點」的參數法

同一顆撈卡片的函式會被好幾個呼叫端用：單篇相關文章、首頁區塊、指定子分類的頁面區塊。
客戶對每個呼叫端的裁定**常常不同**，而且是不同日期各自定的：

| 呼叫端 | 不足時補位？ | 精選優先？ |
|---|---|---|
| 單篇相關文章 | 補其他同類文章 | 否（維持日期序） |
| 指定子分類的頁面區塊 | **不補**，有幾篇顯示幾篇，0 篇整塊不輸出 | 是 |
| 首頁／404 區塊 | 補 | 是 |

**規則：加參數，不改預設行為。** 新裁定做成預設 `false` 的參數，只有被裁定的那個呼叫點傳 `true`；
其他呼叫端一行不改。

```php
function st_pick_cards($sub, $parent, $count, array $exclude = [],
                       $fill = true, $featured_first = false) {
    $ids = [];
    if ($sub) {
        if ($featured_first) $ids = st_featured_ids($sub->term_id, $count, $exclude);
        if (count($ids) < $count) $ids = array_merge($ids, st_latest_ids($sub->term_id, $count - count($ids), array_merge($exclude, $ids)));
    }
    if ($fill && count($ids) < $count) {
        $ids = array_merge($ids, st_latest_ids($parent->term_id, $count - count($ids), array_merge($exclude, $ids)));
    }
    return $ids ? st_render_cards(st_query_in_order($ids)) : '';
}
// 單篇相關文章：st_pick_cards($sub, $parent, 3, [$post_id]);            // 預設
// 指定子分類區塊：st_pick_cards($sub, $parent, 3, [], false, true);   // 不補位、精選優先
```

為什麼不直接改函式的預設：改預設一定連另一邊一起改掉，而另一邊的裁定日期與內容不同；
加參數可以用 diff 證明邊界——「沒傳參數的呼叫端輸出逐字相同」是可以機器驗的（第八節）。

同一原則的另一面：**兩份幾乎逐行相同的撈文程式要抽成一份。** 實案裡「同子分類優先、不足補其他」
曾在兩顆函式各有一份，改規則漏了一邊，審查退回後才抽出來；抽出前後要對所有呼叫端做輸出 `===` 比對。

## 五、分類查詢的三個陷阱

**1. `category__in` 不含子分類，`cat` 含。** 要「某大類底下全部」用 `cat`；
要「只掛這個分類本身」才用 `category__in`。混用會在加子分類那天靜默漏文。

**2. 「分類全部落在某子樹內」的文章怎麼撈。** 需求像「服務項目文只掛在服務子樹，
雙掛了衛教分類的真衛教文不算」，寫法是 `cat` 子樹根 ＋ `category__not_in` 其餘全部分類 id，
結果用 static 快取（一次請求內多處會用到）：

```php
function st_only_in_tree_ids($root_slug) {
    static $cache = [];
    if (isset($cache[$root_slug])) return $cache[$root_slug];
    $root = get_term_by('slug', $root_slug, 'category');
    if (!$root || is_wp_error($root)) return $cache[$root_slug] = [];
    $children = get_term_children($root->term_id, 'category');
    $tree     = array_merge([(int) $root->term_id], is_wp_error($children) ? [] : array_map('intval', $children));
    $others   = get_terms(['taxonomy' => 'category', 'hide_empty' => false, 'fields' => 'ids', 'exclude' => $tree]);
    return $cache[$root_slug] = get_posts([
        'post_type' => 'post', 'post_status' => 'publish', 'fields' => 'ids', 'posts_per_page' => -1,
        'cat' => $root->term_id, 'category__not_in' => $others,
        'ignore_sticky_posts' => true, 'no_found_rows' => true,
    ]);
}
```

好處：編輯多勾一個分類，文章就自動回到一般清單，不必寫死 slug 或 id。
要讓彙整頁的分頁與總篇數也跟著對，排除要做在 `pre_get_posts` 改主查詢，不要在模板裡跳過。

**3. 共用的「取頂層分類」函式不要讀全域查詢的第一篇。** 彙整頁第二頁的第一篇可能屬於另一個子分類，
結果會隨分頁改變。要從 `get_queried_object()` 或傳進來的 `$post_id` 取。

另外兩條容易混掉的規則，實案裡是**兩條不同的規則、刻意不合併**：
「整個子樹排除」（含雙掛的文章）與「只排除只掛該子樹的」（雙掛的保留）。
需求不同就寫成兩個函式，只共用找分類的 slug 寫法。

## 六、兩站 slug 不同步：別名雙認，以及防呆會吞錯誤

Local 與正式站各自建立分類時，slug 幾乎一定會有幾個不同（一邊 `case-anti-aging`、
一邊 `case-longevity`）。程式裡任何寫死 slug 的地方都會在其中一站撈空。

**過渡期做法：正規 slug 找不到依序試別名。**

```php
$groups = [
    ['slug' => 'case-pain',       'alias' => []],
    ['slug' => 'case-anti-aging', 'alias' => ['case-longevity']],
];
foreach ($groups as $g) {
    $term = null;
    foreach (array_merge([$g['slug']], $g['alias']) as $candidate) {
        $t = get_term_by('slug', $candidate, 'category');
        if ($t && !is_wp_error($t) && cat_is_ancestor_of($parent_id, $t->term_id)) { $term = $t; break; }
    }
    if (!$term) continue;                 // 查不到就整塊不輸出（見下）
    $block_id = $g['slug'];               // 區塊 id、分頁錨點固定用正規 slug，兩站 HTML 一致
    …
}
```

- `cat_is_ancestor_of()` 那一條必須有：避免別名撞到站上其他同名分類時撈錯包。
- 兩站 slug 統一之後把 `alias` 清空即可，不用改結構。

**「查不到就整塊不輸出」是防呆，也是錯誤靜默。** 它避免線上留一個空標題，
但同時把「slug 打錯／兩站不同步」吞掉——頁面 HTTP 200、沒有 PHP 錯誤、就是少一組。
實案裡正式站少了一整組案例，客戶回報才發現。所以：

> **凡是有這種回退的地方，兩站 term slug 要列進部署後的逐項抽驗：數「該出現幾組、幾張卡」，
> 不是看 200。**

驗別名分支不能只在有正規 slug 的那一站 curl（永遠走正規那條、測不到別名）。
做法是暫時把本機 term 的 slug 改成另一站的值 → curl 數組數與卡數 → `trap … EXIT` 還原並讀回確認。

同源教訓：回退值傳空字串＝「正式站欄位沒填」變成靜默消失的元素；同一個欄位在不同檔案的回退值要一致。
細節在 `docs/02-ACF規範.md` 第三節。

## 七、預設精選圖外掛會讓 `has_post_thumbnail()` 失真

裝了 Default Featured Image 這類外掛之後，它在 `get_post_metadata` 把預設圖 id 寫進
`_thumbnail_id` 的 meta 快取——**設了預設圖之後，`has_post_thumbnail()`、`get_post_thumbnail_id()`、
`metadata_exists()` 對沒圖的文章全部回「有」。** 兩個後果：

1. 「有自己的精選圖才顯示內頁頂端大圖」這類判斷失效，每篇都出預設圖。
2. 外掛對「頁面」也生效，SEO 外掛會把預設圖當成 `og:image` 寫進分享預覽與 JSON-LD。
   實案裡客戶一上傳預設圖，首頁與幾篇無圖文章的分享預覽當場全變成 600×400 的預設圖。

常見的裁定是：**預設圖只給文章列表的卡片用**；內頁大圖、上下篇縮圖、分享圖都不吃它。做法分兩層：

```php
// 判斷「有沒有自己的精選圖」：比對外掛的 dfi_image_id，不信 has_post_thumbnail()
function st_own_thumbnail_id($post = null) {
    $thumb = (int) get_post_thumbnail_id($post);
    $dfi   = (int) get_option('dfi_image_id');        // 外掛沒裝或沒設圖時是 0
    return ($thumb && $thumb !== $dfi) ? $thumb : 0;
}

// 分享圖：正在瀏覽的那一頁本身不套預設圖，SEO 外掛拿不到圖就走它既有的回退圖
add_filter('dfi_thumbnail_id', function ($dfi_id, $post_id) {
    if (did_action('wp') && is_singular() && (int) $post_id === (int) get_queried_object_id()) return 0;
    return $dfi_id;
}, 10, 2);
```

- 用外掛自己的 filter 從來源擋，不要比對檔名或網址——換一張預設圖、產生各尺寸或 `.webp` 都不會壞。
- 同一頁上的**其他**文章（相關文章卡、彙整卡）post id 不同，照常拿到預設圖。
- 已知邊界：某篇剛好親手選了與預設圖同一張附件，會被當成沒圖。
- 已知風險：外掛用 `wp_cache_set` 寫 `post_meta` 群組，主機若開持久化物件快取，filter 可能不跑。
  日後分享圖又變回預設圖，先查這裡。

## 八、驗證法：命令列跑函式，做改前改後輸出比對

純資料層的改動（撈法、排序、補位、抽共用函式）用截圖或肉眼看頁面**證明不了「輸出沒變」**。
正路是在 Local 用 php CLI 載 `wp-load.php`，直接呼叫主題函式、把輸出存檔比對：

```php
<?php // scratchpad/compare.php —— 放 scratchpad，不要寫進網站目錄或主題目錄
define('WP_USE_THEMES', false);
$_SERVER['HTTP_HOST'] = 'your-site.local';
require '/path/to/Local/site/app/public/wp-load.php';

function st_compare_one($pid) {               // 包進函式：避免 setup_postdata() 蓋掉頂層變數
    $GLOBALS['post'] = get_post($pid);        // 每次呼叫前重設 global $post
    setup_postdata($GLOBALS['post']);
    return md5(st_related_cards($pid, 3));
}
foreach ([101, 102, 103] as $pid) {
    echo $pid, ' ', st_compare_one($pid), PHP_EOL;
}
```

跑法：Local 內建的 php 加 `-d mysqli.default_socket=<該站 socket>`（路徑與 incantation 見
`AGENTS.md` 硬規則 7 與 `docs/05-踩坑清單.md`）。改前跑一次存檔、改後跑一次，`cmp`／`diff` 逐字相同才算通過。
**沒開新參數的呼叫端輸出逐字相同**是第四節那種改動的審查第一關。

這種 bootstrap 腳本有四個會讓結果看起來「全部 DIFF」、其實是腳本錯的坑：

1. **頂層不要用 `$id` 當迴圈變數。** `setup_postdata()` 會寫 `$GLOBALS['id']`，
   `foreach ($posts as $id)` 在頂層會被卡片渲染蓋掉，印出來的 slug 全是最後一張卡。把比對包進函式就好。
2. **每次呼叫前重設 global `$post`。** 卡片渲染依賴 `$post`；同一篇先呼叫舊版再呼叫新版，
   md5 會不同，純粹是呼叫順序造成。兩種順序都跑才算證據。
3. **用 `wp_get_object_terms` filter 模擬打標籤時，參數是字串。** `$object_ids` 是逗號字串、
   `$taxonomies` 是帶單引號的 `'post_tag'`，用 `(array)`／`reset()` 會錯，要 `trim(…, "' ")`。
4. **Local 站沒開**時腳本回整頁「Error establishing a database connection」HTML，
   先確認 Local App 有 Start，不要開始追程式。

另外兩條與資料分布有關：

- **只有 Local 樣本時，交審前先看正式站的資料分布**（哪個子分類幾篇、幾篇雙掛）。
  補位規則在「子分類剛好不足」時才會走到，Local 樣本若湊巧都夠，等於沒測。
- **別名分支、補位分支要製造條件去測**（第六節的暫改 slug 法；或 `trap` 暫時改分類），
  不是跑一次預設路徑就宣稱通過。
